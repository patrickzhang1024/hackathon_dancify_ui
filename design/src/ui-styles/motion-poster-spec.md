# Motion Poster 02 · 详细 UI/UX 设计规格

## 0. 设计定位

Motion Poster 不是传统的音乐后台，也不是普通的数据报告页。它把“音乐被 AI 读懂之后形成的舞蹈”做成一张可以播放、滚动、选择和继续探索的动态海报。

**核心承诺：** 用户在 30 秒内完成三件事：看懂这首歌的感觉、看到感觉如何变成动作、选择一个方向继续播放。

**一句话体验：**

> Music has a body. / 音乐有了身体。

## 1. 目标用户与场景

### 主要用户

- 对音乐、舞蹈和视觉艺术感兴趣的普通用户。
- 想快速找编舞灵感的创作者。
- 在现场演示或作品集里体验 AI 音乐理解的观众。

### 首要场景

1. 用户上传一首歌，等待分析完成。
2. 用户浏览音乐画像，理解节奏、情绪、能量和曲风。
3. 用户在三个方向中选择一个，查看虚拟角色跳舞。
4. 用户在播放页切换段落、动作版本和播放状态。

### 设计不追求

- 一次性展示所有算法参数。
- 模拟 DAW 的高密度编辑界面。
- 让用户先学习 BPM、valence、arousal 等术语。

## 4. 模块详细设计

## 4.1 Header / 顶部导航

### 目标

建立品牌识别，并提供两个核心锚点：查看音乐解释、查看编舞方向。

### 界面组成

- 左侧：`DANCIFY°`，点击返回方案总览或新建分析。
- 右侧链接：`THE READ`、`3 MOVES`。
- 右侧按钮：`STYLE 02 ＋`，打开三个视觉方案的切换菜单。

### 交互

- 点击 `THE READ`：平滑滚动到音乐画像区。
- 点击 `3 MOVES`：平滑滚动到编舞方向区。
- 点击 `STYLE 02 ＋`：打开下拉菜单，当前项高亮。
- 菜单外点击或按 `Escape`：关闭菜单。
- 键盘 Tab 顺序：Logo → THE READ → 3 MOVES → STYLE。

### 状态

| 状态 | 表现 |
| --- | --- |
| 默认 | 透明背景，底部深色细线 |
| Hover | 链接下方出现短横线 |
| 当前区块 | 文本颜色加深，短横线保持 |
| 菜单打开 | 菜单贴近按钮，黄色底，当前版本标记 |
| 移动端 | 隐藏两个锚点，只保留 Logo 和 Style |

### 文案

- 使用 `THE READ` 而不是 `REPORT`，强调解释而不是数据输出。
- 使用 `3 MOVES` 而不是 `VARIANTS`，让普通用户知道这里是三种舞蹈可能。

## 4.2 Hero / Track Poster 主海报

### 目标

第一眼呈现产品的独特价值：一首歌正在变成一个会动的身体。

### 内容层级

1. 歌曲元信息：`TRACK / 001`、时长、BPM。
2. 主标题：歌曲名，允许两行超大排版。
3. 音乐解释：不是营销 slogan，而是对这首歌的具体阅读。
4. 主行动：`PLAY THE MOVEMENT`。
5. 角色：代表当前选中的编舞方向。
6. 版本编号：角色旁显示 `02`，暗示它是三种可能中的一种。
7. 右侧印章：`AI CHOREOGRAPHY / LIVE VISUAL STUDY / 2026`，作为作品语境，而不是功能信息。

### 视觉规则

- 标题是最大元素，使用压缩、厚重、带海报感的字体。
- 标题不超过两行；歌曲名过长时使用自动缩放或截断规则。
- 角色不做写实 3D，而用高对比的抽象剪影/色块占位，避免与真实 three.js 模型争夺视觉身份。
- 主标题、角色和按钮形成三角构图；播放按钮不能放在页面最底部孤立存在。

### 交互

- 点击主播放按钮：播放音频并启动角色动作。
- 播放后按钮文案变为 `PAUSE THE MOVEMENT`。
- 角色播放时轻微位移或缩放，不能持续大幅摇晃。
- 点击角色编号或方向名称：跳转至 `3 MOVES` 并选中对应方向。

### 状态

| 状态 | 主按钮 | 角色 | 文案 |
| --- | --- | --- | --- |
| 未播放 | `PLAY THE MOVEMENT` | 静止 | 无额外提示 |
| 播放中 | `PAUSE THE MOVEMENT` | 随节拍动作 | 可显示 `LIVE / SYNCED` |
| 暂停 | `PLAY THE MOVEMENT` | 保留当前姿态 | 进度不丢失 |
| 资源加载 | `LOADING THE BODY…` | 骨架/渐变占位 | 显示加载进度 |
| 音频失败 | `TRY AGAIN` | 静止 | 告知音频无法播放原因 |

## 4.3 Poster Play / 播放入口

### 目标

在海报中提供一个只有一个主动作的按钮：让音乐开始拥有身体。

### 视觉

- 胶囊形外框，黄色底色。
- 左侧圆形深色播放图标。
- 右侧使用全大写等宽字。
- 按钮尺寸足够大，桌面端至少 190 × 52 px，移动端至少 220 × 52 px。

### 交互细节

- Hover：按钮向上移动 2 px，阴影加深。
- Pressed：按钮回落，播放图标变为暂停。
- 播放开始：背景球体和人物同步开始动效，按钮不做闪烁。
- 用户点击空格键：触发播放/暂停，但仅在页面不处于输入框时响应。

## 4.4 The Read / 音乐画像模块

### 目标

把六项分析结果压缩成一段有观点的音乐解释。这里不是“完整报告”，而是用户继续探索的理由。

### 内容结构

#### A. 区块标识

- 竖排文字：`THE READ`。
- 小标签：`MUSIC PROFILE`。

#### B. 核心判断

示例：

```text
Joyful,
not weightless.
```

它要同时包含情绪和一个有辨识度的转折，避免“Energetic / Bright / Fun”这类通用标签堆砌。

#### C. 解释段落

示例：

> The rhythm is exact. The emotion is expansive. The strongest movement arrives when the chorus releases its stored energy.

文案需要回答：哪些音乐特征最重要，以及它们如何影响动作。

#### D. 三个核心指标

- `AROUSAL`：动作能量/兴奋度。
- `VALENCE`：情绪明暗和积极程度。
- `DENSITY`：节奏密度和动作换招压力。

六项指标的完整结果可在后续“详细报告”版本中展开；Motion Poster 只保留能影响观看和选择的三个值。

### 数据表现

- 使用巨大数字，不使用默认雷达图。
- 数字旁配小型英文标签。
- 数字由下向上出现，时间错开 80–120 ms。
- 数字应有可访问文本，例如 `Arousal 84 out of 100`。

### 交互

- 指标 Hover：显示一句解释，例如 `84 / chorus energy rises sharply`。
- 点击某指标：高亮 Hero 或时间线中对应的视觉证据（P1）。
- 滚动进入模块时，数值从 0 或短横线动画到最终值。

## 4.5 3 Moves / 编舞方向模块

### 目标

让用户看到三个真正不同的创意方向，并理解差异来自哪里。

### 三个方向定义

| 方向 | 动作语言 | 适合表达 | 默认色 |
| --- | --- | --- | --- |
| Grounded Groove | 低重心、连续脚步、站立为主 | 稳定律动 | 青绿色 |
| Neon Release | 大幅度、跳跃、快速方向变化 | 副歌释放 | 珊瑚红 |
| Soft Gravity | 流动、延展、地面动作 | 温暖与抒情 | 紫色 |

### 卡片内容

- 编号和关键词：`01 / LOW`。
- 方向名称：两行大标题。
- 一句话动作描述。
- 预览状态。
- 选中状态。

### 交互

- Hover：卡片背景切换为该方向的主色，文字反转。
- Click：卡片保持 selected，并切换 Hero 角色/播放脚本。
- 键盘 Enter/Space：选择卡片。
- 选择后：页面不自动播放，避免用户在浏览时突然发声；显示 `PLAY THIS DIRECTION`（P1）。
- 当前选择需要有非颜色标识：边框、编号或 `SELECTED` 标签。

### 质量要求

三个卡片必须在以下至少三项上不同：

- 舞种词汇。
- 身体状态。
- 能量强度。
- 空间方向。
- 动作连续性。

只换颜色或只换标题，不算有效差异。

## 4.6 Footer Timeline / 音乐时间线

### 目标

把页面从“海报”连接回真实音乐，让用户知道视觉变化发生在哪个段落。

### 内容

- 迷你波形。
- 播放进度条。
- 段落标签：`INTRO`、`VERSE`、`CHORUS`、`DROP`、`OUTRO`。
- 当前进度和总时长。

### 交互

- 点击进度条：跳转到对应音频位置。
- 点击段落标签：跳转到段落开始处。
- 当前段落使用黄色或珊瑚色高亮。
- 进度条拖拽时显示时间 tooltip（P1）。

### 播放同步

```text
expectedBeat = audioTime × bpm / 60
currentSection = sectionAt(audioTime)
currentMove = moveAt(expectedBeat)
```

界面以音频时间为唯一主时钟；角色动作和段落高亮跟随音频，不以渲染帧数作为时间基准。

### 状态

- 未播放：进度条停在初始位置。
- 播放中：进度条和波形游标同步移动。
- 拖动中：暂停自动更新，松开后跳转并继续/保持暂停。
- 音画重新同步：短暂显示 `RESYNCING`，不清空当前方向。

## 4.7 Background Orbs / 背景能量层

### 目标

将音乐的能量和编舞方向转译成环境变化，让页面具有现场感，但不干扰内容。

### 规则

- 橙色球体：当前动作/视觉焦点。
- 黄色球体：音乐的明亮情绪或能量高点。
- 深蓝底：承载文字和人物的稳定背景。
- 球体移动速度应低于人物动作速度，形成“环境慢、动作快”的层次。

### 动态映射（P1）

```text
energy 0–0.35 → 背景静止、模糊度高
energy 0.36–0.70 → 球体缓慢位移
energy 0.71–1.00 → 球体扩大、对比度提高
```

### 无障碍

- `prefers-reduced-motion: reduce` 时关闭球体移动和人物自动动作。
- 颜色变化不能承担唯一信息，必须同步更新文字或标签。

## 4.8 Language Toggle / 中英文切换

### 目标

让中文用户可以完整理解产品价值和音乐解释，同时保留英文海报版的视觉语气。语言切换只改变内容语言，不改变当前歌曲、播放进度、选中方向或视觉主题。

### 界面

- 放置在 Header 右侧 Style 菜单旁。
- 使用紧凑胶囊按钮：`中 / EN`。
- 当前语言高亮，另一语言降低不透明度。
- 桌面端显示完整 `中 / EN`；移动端保留同样按钮，不用下拉菜单替代。

### 覆盖范围

- `THE READ` → `音乐解读`。
- `3 MOVES` → `3 种编舞`。
- `STYLE 02` → `风格 02`。
- Hero 元信息、音乐解释、播放按钮。
- `THE READ` 模块标题、指标标签和解释。
- 三个编舞方向的关键词、标题和描述。
- 时间线段落：`INTRO / VERSE / CHORUS / DROP / OUTRO` → `前奏 / 主歌 / 副歌 / 爆发 / 尾奏`。

歌曲名 `MIDNIGHT BLOOM` 保持原文，避免专辑/歌曲名称被误翻译。

### 行为

- 默认语言为英文；若用户之前选择过语言，则读取本地偏好。
- 点击后立即切换，不刷新页面。
- 切换过程中保留播放状态、进度和当前方向。
- 切换为中文时，按钮 aria-label 为 `切换到英文`；切换为英文时为 `切换到中文`。
- `html[lang]` 同步更新为 `zh-CN` 或 `en`。
- 中文文案允许 1–2 行自然换行，不用为了适配英文海报强行截断。

### 文案原则

- 中文不是逐字翻译，要保留 Motion Poster 的短句、节奏和画面感。
- 使用“音乐解读”“音乐画像”“编舞方向”等用户能理解的词，不暴露内部模块名。
- 播放动作使用“播放这段舞蹈 / 暂停这段舞蹈”，比“播放动作脚本”更符合用户语境。

## 5. 全局交互与状态模型

```text
IDLE
  ├─ play → PLAYING
  ├─ select direction → SELECTED
  └─ scroll → section focus

PLAYING
  ├─ pause → PAUSED
  ├─ seek → SEEKING → PLAYING
  ├─ section change → UPDATE_SECTION
  └─ error → ERROR

SELECTED
  ├─ play → PLAYING
  └─ select another → SELECTED
```

### 全局反馈

- 不使用阻塞式弹窗承载普通状态。
- 载入、同步和失败使用页面内文案。
- 错误文案必须给出下一步动作，例如 `Audio could not be decoded. Try an MP3 or WAV under 50 MB.`

## 6. 视觉设计 Token

### 色彩

| Token | Hex | 用途 |
| --- | --- | --- |
| Ink | `#140D35` | 文字、描边、主对比 |
| Violet Field | `#3C26C8` | Hero 主背景 |
| Coral Motion | `#FF6647` | 动作、能量、选中态 |
| Signal Yellow | `#FFDD55` | 标题、主 CTA、指标 |
| Soft White | `#F4F0E5` | 内容背景 |

### 字体

- Display：压缩粗体/海报字体，建议 `Impact` 作为原型 fallback，生产版替换为许可明确的 condensed display font。
- Body：Arial/Helvetica 类无衬线，保证大字号短文案可读性。
- Utility：等宽字体，用于 BPM、时间、编号、状态和导航标签。

### 形状

- 海报区块：硬边、少圆角。
- CTA：大胶囊形，作为唯一明显的圆润组件。
- 指标区：直角或细边框，不使用通用玻璃拟态。
- 角色：硬描边和明显色块，强化“海报剪影”而不是拟真角色。

### 间距

- 桌面页面边距：32–48 px。
- Hero 标题与顶部导航至少保持 48 px 呼吸空间。
- 模块之间使用 2 px 深色分隔线，避免大量卡片阴影。
- 移动端边距：18–22 px。

## 7. 动效规格

### 动效节奏

- 页面进入：标题先出现，角色延迟 120 ms，按钮延迟 220 ms。
- 数值出现：每个指标间隔 80–120 ms。
- 卡片 Hover：150–200 ms。
- 页面滚动定位：400–600 ms。
- 播放反馈：人物 1–1.5 秒循环；背景球体 3–6 秒循环。

### 动效原则

- 只让一个主视觉元素在每个时刻承担最强运动。
- 播放时人物是主运动，背景是次运动，文字基本保持稳定。
- 不使用无限闪烁、持续抖动或全页面缩放。

## 8. 组件状态验收清单

设计稿至少需要提供以下状态：

- Header 默认、Hover、菜单打开、移动端。
- Hero 未播放、播放中、暂停、资源加载失败。
- 主播放按钮默认、Hover、Pressed、Disabled。
- The Read 数值加载中、已加载、低置信度。
- Move 卡片默认、Hover、Selected、Keyboard focus、生成失败。
- Timeline 未播放、播放中、拖拽中、当前段落高亮。
- Reduced motion 模式。

## 9. 与后端/算法数据的映射

| UI 内容 | 数据来源 | 备注 |
| --- | --- | --- |
| 歌曲名/时长 | Audio metadata | 本地读取，不依赖 LLM |
| BPM | `CriteriaReport.rhythm` | 允许显示整数 |
| Hero 解释 | `RefinedReport` | LLM 生成后需限制长度 |
| Arousal/Valence/Density | `CriteriaReport.emotion/rhythm` | 映射到 0–100 |
| 段落标签 | `CriteriaReport.structure.sections` | 低置信度时显示实验性标记 |
| 三个方向 | `CreativeBrief[]` | 每个方向有颜色和一句话描述 |
| 当前动作 | `MotionControlScript.timeline` | 由 beatGrid 映射到音频时间 |
| 播放进度 | Audio currentTime | UI 不自行计时 |

## 10. MVP 与后续版本

### MVP 必做

- Hero 海报。
- 主播放按钮。
- The Read 三指标。
- 三个编舞方向卡片。
- 基础波形、进度条和段落标签。
- 方向选择和播放/暂停状态。
- 桌面端和移动端响应式。

### P1

- 指标点击联动时间线证据。
- 方向短片段预览。
- 拖拽进度 tooltip。
- 真正的 three.js 角色替换抽象角色。
- 根据能量动态改变背景球体。

### P2

- 导出视频或分享海报。
- 保存编舞版本。
- 歌词滚动与情绪段落联动。
- 用户调整动作强度、镜像和朝向。

## 11. 设计交付标准

第一轮交付建议包括：

1. Desktop 1440 px 高保真首页/海报页。
2. Desktop 1440 px The Read 和 3 Moves 完整长页面。
3. Mobile 390 px 长页面。
4. 播放、暂停、选中、菜单、加载、错误六类状态。
5. 设计 Token：色板、字体、间距、描边、动效时长。
6. 给开发的组件命名和交互注释。
7. 至少一张“音乐特征 → 视觉/动作变化”的映射说明。

## 12. 评审问题

- 用户是否在 Hero 里理解了“音乐 → 身体”的关系？
- `The Read` 是否像一个有观点的解释，而不是普通仪表盘？
- 三个方向是否真的有动作和情绪上的差异？
- 用户是否知道哪个按钮会让声音开始？
- 播放时是否能看出当前段落和动作的关系？
- 海报感是否保留了足够的可用性？
- 去掉所有动效后，页面是否仍能理解？
